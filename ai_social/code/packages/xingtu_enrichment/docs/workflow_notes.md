# 星图创作者检索流程说明

## 录制样本来源

本次整理基于录制文件：

- `/home/tuo/project/ai_social/tmp/recordings/xingtu_clean_recording.ts`

这个文件被视为“行为样本”，不是最终实现。它可以帮助我们识别真实业务流程，但不能直接作为长期维护代码。

## 从录制中推断出的真实业务流程

1. 进入星图首页，使用已登录态打开工作台。
2. 如果首页出现账号/工作区卡片，需要先点选目标账号入口。
3. 进入 `找达人` 页面。
4. 在筛选区按“筛选组 -> 下拉菜单 -> 选项”的方式应用条件。
5. 在结果列表里点击某个达人条目。
6. 达人详情页以弹窗新页形式打开。
7. 在详情页读取关键指标，而不是对指标卡做无意义点击。

## 信号与噪声拆分

### 保留的信号

- 首页到工作区的进入动作
- `找达人` 导航入口
- 类似 `美妆 -> 美妆测评种草` 的筛选交互模式
- 类似 `家居家装 -> 全选` 的下拉筛选模式
- 结果区点击达人，打开详情页
- 详情页可提取的关键指标结构

### 删除的噪声

- 对同一指标文本的重复点击
- 只为“看一眼页面”而发生的随机卡片点击
- 没有改变页面状态的指标卡点击
- 与导航无关的页面噪声操作

### 用可维护抽象替代的部分

- 登录态由外部注入，不放在主工作流内
- 工作区账号选择独立成函数
- 筛选逻辑抽成通用 helper，不保留录制式逐行点击
- 详情页打开逻辑抽成“弹窗或同页”统一处理
- 指标提取优先走结构化选择器，失败时再回退到整页文本解析

## 当前代码落点

- `app/services/xingtu_workflow.py`
  星图主工作流，包含首页进入、账号选择、进入找达人、应用筛选、打开详情页、提取详情数据等函数。

  统一维护选择器。已根据录制补充了首页账号卡片、筛选下拉菜单、结果区和详情页相关选择器。

- `app/schemas/xingtu.py`
  统一维护筛选配置、结果行结构、详情页结构。详情结构已补充录制中能观察到的核心指标字段。

## 当前仍然脆弱的点

- 首页账号卡片目前仍然依赖文本匹配，缺少真正稳定的数据属性。
- `找达人` 导航目前仍以 role + 文本为主，后续最好补稳定容器或测试属性。
- 筛选下拉菜单的 DOM 结构可能会因前端版本变化而变化。
- 结果列表可能是表格，也可能是卡片列表，当前代码已做双通道回退，但还不够“硬”。
- 详情页指标有些是结构化卡片，有些更像整页文本拼接，当前用了“结构化优先 + 文本回退”策略。
- 详情页是否新开弹窗，与账号状态和页面实现有关；当前逻辑已显式处理，但仍建议后续用真实页面再校验一次。

## 后续建议

1. 用真实页面 DOM 再校准一次账号卡片与筛选菜单选择器。
2. 明确结果区到底是“表格优先”还是“卡片优先”，然后收紧结果项选择器。
3. 为详情页关键指标补快照测试或静态 HTML 解析测试。
4. 把 `named_filters` 与业务模板做更明确的映射，减少页面文案变化带来的影响。
5. 在调用侧通过配置或环境变量传入 storage state 路径，不把认证状态写死在工作流实现里。
6. 统一通过 `app/core/config.py` 推导工作区路径，避免脚本里散落旧绝对路径。
