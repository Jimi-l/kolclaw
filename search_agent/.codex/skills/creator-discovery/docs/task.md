# creator-discovery / Task Definition

## 一、任务定义

本 skill 的任务不是“泛泛找达人”，而是从抖音内容流中识别 **值得进入后续商业评估链路** 的潜力账号。

它强调：

- 快速筛掉低价值内容
- 稳定识别爆款信号
- 通过主页与近期内容补足判断
- 形成可复用的结构化记录

---

## 二、任务对象

### 直接对象
- 抖音推荐流中的视频
- 视频对应的达人主页

### 最终对象
- 值得进入星图补齐和后续二筛的达人记录

---

## 三、任务拆分

### 子任务 1：快速视频筛选
目的：
- 用尽量低的浏览成本识别潜力内容

输出：
- `pass / skip`

### 子任务 2：基础数据采集
目的：
- 把视频层的基础数据提出来

输出：
- 视频链接
- 发布时间
- 互动数据
- 达人名称
- 粉丝量

### 子任务 3：主页分析
目的：
- 判断达人是否只是偶发爆款，还是具有持续价值

输出：
- 推荐视频位置
- 推荐视频点赞
- 最近 3 条视频点赞
- 平均值
- 流量趋势

### 子任务 4：标签判断
目的：
- 让下游知道这个达人“是什么人”“发什么内容”“适合什么广告形式”

输出：
- 人设标签
- 内容标签
- 场景标签
- 广告类型

### 子任务 5：记录生成
目的：
- 让结果进入统一 schema

输出：
- 合格 discovery record

---

## 四、业务意义

这个 skill 的业务价值，不是“多刷几个号”，而是把原本依赖人工经验的第一轮粗筛，沉淀为可执行、可解释、可规模化的动作。

它是整个链路中的：

- 前端入口
- 候选池生成器
- 标签标准化器
- 星图补齐前的质检层

---

## 五、最重要的判断点

本 skill 最核心的不是“看没看视频”，而是下面四个判断：

1. 这条视频是不是潜力视频？
2. 这个达人是不是值得留下？
3. 这个达人近期流量是偶发还是稳定？
4. 这个达人适合哪类商业合作？

只要这四个判断不稳，后面的链路都会变脏。

---

## 六、输入不足时的处理

若没有行业/预算/人群等额外约束：

- 按通用潜力达人逻辑执行
- 优先保证内容本身与账号持续性判断正确

若有额外约束：

- 可以在标签判断和 notes 中体现
- 但不能因为有 brief 就跳过基础流量判断

---

## 七、完成标志

本 skill 结束时，应该得到的是一批：

- 已结构化
- 已去重
- 已有标签
- 已能解释
- 已能进入 xingtu enrichment

的 discovery records，而不是一段自然语言巡号总结。
