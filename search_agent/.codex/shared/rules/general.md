# General Rules

本文件为 `search_agent` 的全局规则。

## 1. 绝不伪造

- 未看到的数据不填
- 未确认的达人不匹配
- 推断值必须在备注中说明为推断

## 2. 原始值与标准值并存

对于以下字段，尽量同时保留：

- 粉丝数
- 点赞数
- 评论数
- 收藏数
- 转发数
- 价格
- 播放量
- 百分比指标

示例：

- `follower_count_raw = "12.5万"`
- `follower_count_normalized = 125000`

## 3. 状态显式化

任何失败都不能默默吞掉，必须写成状态：

- `blocked`
- `skipped`
- `xingtu_not_found`
- `ambiguous_match`
- `field_partial`

## 4. 中文说明，英文字段

- 说明文档、备注、原因：中文
- 结构化字段名：英文 snake_case

## 5. 去重优先

发现新记录时先做去重：

### 基础去重键
`platform + creator_name`

### 辅助校验项
- 粉丝量量级
- 头像/昵称相似性
- 内容方向是否一致

若可能重复：
- 不直接新建
- 先进入 `manual_review` 或合并逻辑

## 6. 只在真正阻塞时打断

允许自动继续的情况：

- 某个字段缺失
- 某一条达人跳过
- 某个视频不达标
- 某条记录不适合补齐

必须打断或显式上报的情况：

- 登录失效
- 验证码/人机验证
- 页面无法访问
- 无法判断当前账号是否匹配
- 表格/数据源不可写

## 7. 不做过度 UI 探索

任务只围绕当前 skill 的必要路径执行：

- 不多点无关页面
- 不为了“看一眼”额外跳转复杂流程
- 不引入新的状态来源

## 8. 记录异常原因

每次跳过或失败，至少记录一句原因：

- `广告内容，直接跳过`
- `直播间，不进入分析`
- `星图搜索无结果`
- `同名达人过多，无法确认`

## 9. 输出要可接续

任何阶段的输出都要能被下一阶段直接消费。
不要只输出自然语言总结，而没有结构化记录。

## 10. 优先稳定，不优先炫技

这个项目的目标是让流程能稳定复用，而不是一次性完成复杂展示。
任何设计都优先考虑：

- 可重复
- 可检查
- 可回填
- 可扩展
