# Merge 目录说明

这份目录是两份原始转发聊天数据统一处理后的最终输出目录，面向业务同学和技术中台使用。

## 目录概览

- 当前一共 `84` 个聊天文件。
- 其中 `65` 个是双人聊天文件。
- 其中 `19` 个是群聊文件。
- 当前所有文件合计约 `4470` 条消息。
- 按 `senderDisplayName` 去重后，当前一共出现 `94` 个微信名。

说明：

- 这里的“94 个微信名”是按原始聊天里的显示名直接去重统计，不做达人名、媒介名、别名合并。
- 因为我们保留原始聊天内容，里面会有少量占位式或不完整名称，例如 `.`、`。`、`= =`、`001` 这类名字也会被计入统计。

## 文件名怎么理解

- 双人聊天文件命名方式：`A__B.json`
- 群聊文件命名方式：`群聊__序号__A__B__C.json`

可以直接把文件名理解为“这个文件里主要是哪几个微信名在说话”。

## 文件里是什么内容

每个 `json` 文件都是一个消息数组。

每条消息只保留 4 个字段：

- `localId`：消息在当前文件里的顺序编号
- `type`：消息类型，目前大多是 `文本消息`
- `content`：消息正文，保留原始聊天内容
- `senderDisplayName`：这条消息显示是谁发的

示例结构：

```json
[
  {
    "localId": 1,
    "type": "文本消息",
    "content": "你好，这边发你 brief",
    "senderDisplayName": "小被罩儿"
  }
]
```

## 内容特点

- 保留了原始聊天里的正文内容，不做话术修正。
- 链接、报价、返点、档期、授权、入库资料、付款信息、`[图片]`、`[消息]` 等内容都会原样保留。
