## 二、这个文件的价值所在

这个文件的价值不在于"话术模板"本身（虽然也很有价值），而在于：

### 1. **完整的业务认知框架**
   - 媒介团队是怎么**看待**达人建联这件事的？
   - 他们把整个流程拆解成了哪些**阶段**和**场景**？
   - 他们关注达人的哪些**维度**（标签体系）？

### 2. **经过验证的话术结构**
   - 不是随便的句子，而是**结构化**的信息收集模板
   - 比如"场景一"的询价话术，一次性问 4 个关键问题：价格、返点、改价、档期
   - 这是经过无数次沟通迭代出来的**有效信息结构**

### 3. **场景化的思维方式**
   - 同样是"砍价"，对"不缺商单的达人"和"性格不友善达人"用不同策略
   - 同样是"建联"，对"已入驻星图"和"未入驻星图"用不同话术
   - **不是"一个话术走天下"，而是 context-aware 的话术策略**

## 三、对我们当前项目的启发

我们当前的 `contact_db` 项目是从**真实会话数据**中学习，而这个 Excel 文件是**专家经验**的沉淀。两者可以互补：

### 启发 1：我们的标签体系可以参考这个 Schema

看"账号标签类型"Sheet，他们把达人标签分成四大类：
1. **账号基础信息**（固定属性）- platform, account_type, verify_status...
2. **粉丝画像标签**（反向匹配核心）- fan_gender_ratio, fan_age, fan_consumption...
3. **流量数据标签**（AI 打分用）- follower_count, avg_play, avg_interact_rate...
4. **商业合作标签**（选号核心）- （文件没展示完，但应该是合作历史、价格区间等）

**我们可以做什么？**
- 我们当前的 `Stage`/`Scene`/`Intent` 标签体系聚焦在**会话内部**
- 但这些**达人侧的属性标签**（粉丝画像、流量数据等）也是重要的 context
- 未来我们的 `TrainingSample` 可以考虑把这些元信息也加进去（如果能拿到的话）

### 启发 2：我们的场景分类可以更细化

看"商务沟通知识库"Sheet，他们定义的 7 个场景：
1. 原创视频
2. 原创图文
3. 线下活动 + 原创视频
4. 线下活动 + 原创图文
5. 线下直播 + 原创视频
6. 线下直播 + 原创图文
7. 其他权益（跨月保价、挂组件、授权投流等）

**对比我们当前的 Scene 枚举：**
```python
class Scene(StrEnum):
    GREETING = "greeting"
    SELF_INTRO = "self_intro"
    ASK_AVAILABILITY = "ask_availability"
    ASK_PRICE = "ask_price"
    EXPLAIN_PRICE = "explain_price"
    BARGAIN = "bargain"
    SEND_BRIEF = "send_brief"
    CONFIRM_SCHEDULE = "confirm_schedule"
    PROMPT_REPLY = "prompt_reply"
    WRAP_UP = "wrap_up"
    SMALL_TALK = "small_talk"
    UNKNOWN = "unknown"
```

**我们可以做什么？**
- 我们当前的 Scene 是**按对话动作**分的（问候、自我介绍、询价...）
- 他们的场景是**按合作形式**分的（原创视频、线下活动、直播...）
- 这两个维度其实是正交的，可以结合：
  - `Scene.ASK_PRICE` + `合作形式=线下活动` → 这是更精细的场景

### 启发 3：话术模板的结构化程度

看他们的一个话术示例（场景一：原创视频）：
```
xxx项目xxx产品
项目背景：（如有）
传播需求：（如有）
账号昵称：xxx
发布时间：尽量给到具体，例如4月20日-4月23日之间
合作平台：抖音/小红书
合作形式：原创视频20s内/21-60s/60s+

辛苦给到以下信息~
1、4月视频20s内/21-60s/60s+价格是多少
2、平台下单可给到平台裸价几个点
3、是否可接受改价下单
4、档期4月20日-4月23之间是否还有
```

**这不是随便写的，而是：**
1. **先给 context**（项目、产品、时间、形式）
2. **再明确要求**（4 个具体问题）

**对比我们从真实会话中挖的模板：**
- 我们的模板可能更"自然"，但也可能更"零散"
- 专家的模板更"结构化"，信息传递效率更高

## 四、具体可以做的几件事

### 第一件事：把这些专家话术作为"种子模板"

我们当前的 `TemplateMiner` 是从真实会话中挖掘模板。但我们可以：
1. 把 Excel 里的这些专家话术也进行**槽位化**处理
2. 作为"高质量种子模板"加入我们的模板库
3. 给这些模板更高的 `business_value_score`（因为是专家验证的）

**槽位化示例（以砍价话术为例）：**
```
原始："老师，客户要求的返点比较高，还能再多给几个点么？"
槽位化："[APPELLATION]，客户要求的返点比较高，还能再多给几个点么？"

原始："后续还会给您推荐其他的客户，这次合作能再多给5%吗？"
槽位化："后续还会给您推荐其他的客户，这次合作能再多给[AMOUNT]吗？"
```

### 第二件事：用专家话术来评估我们挖掘的模板

我们可以做一个**模板质量评估器**：
- 输入：我们从数据中挖的模板
- 参考：Excel 里的专家模板
- 输出：相似度评分 + 改进建议

比如，如果我们挖的模板是：
```
"在吗？问下价格"
```
而专家模板是：
```
"xxx项目xxx产品
项目背景：...
发布时间：...
合作形式：...
辛苦给到以下信息~
1、价格是多少
2、返点几个点
3、档期是否还有"
```

评估器可以指出：
- ❌ 缺少项目 context
- ❌ 只问了价格，没问返点、档期
- ✅ 可以改进为："[APPELLATION]，我们有个[PROJECT]项目想跟您合作，想了解下[DATE_RANGE]的档期和价格..."

### 第三件事：丰富我们的弱标签规则

Excel 文件里有很多关键词和场景对应关系，我们可以用来丰富 `normalizer.py` 里的弱标签规则：

**当前 `KEYWORDS_SCENE`：**
```python
KEYWORDS_SCENE = {
    Scene.GREETING: ["你好", "您好", "在吗", "嗨"],
    Scene.SELF_INTRO: ["我是", "我们是", "公司"],
    Scene.ASK_AVAILABILITY: ["接吗", "合作", "档期", "有时间"],
    ...
}
```

**可以从 Excel 补充：**
```python
# 从"添加新达人知识库"补充
Scene.PLATFORM_INVITATION: ["星图", "蒲公英", "平台邀约"]
Scene.OFFLINE_ACTIVITY: ["线下活动", "活动时间", "活动地点", "差旅"]
Scene.LIVE_BROADCAST: ["直播", "专场", "混播", "直播间"]

# 从"砍价话术场景"补充
Scene.BARGAIN_RETURN_POINT: ["返点", "多给几个点", "最高返点"]
Scene.BARGAIN_LONG_TERM: ["长期合作", "后续推荐", "复投率"]
```

### 第四件事：建立"场景-策略"映射

Excel 文件最有价值的部分是这个逻辑：
```
IF 达人类型 = "不缺商单"
   AND 返点情况 = "已达到标准"
   THEN 话术策略 = "表达认可 + 强调长期合作"

IF 达人类型 = "性格不友善"
   THEN 话术策略 = "直接明了 + 不啰嗦"
```

**我们可以做什么？**
- 虽然当前我们没有"达人类型"标签，但可以从**会话历史**中推断：
  - 如果达人回复很快、档期很满 → 可能是"不缺商单"
  - 如果达人回复简短、语气生硬 → 可能是"性格不友善"
- 然后在我们的 `TalkTemplate` 中增加 `recommended_strategy` 字段
- 未来可以做"策略推荐"：根据当前对话状态，推荐用什么策略回复

## 五、长期一点的想法：专家经验 + 数据驱动的混合系统

纯数据驱动（我们现在做的）和纯专家规则（Excel 文件）各有优劣：

| 方式 | 优点 | 缺点 |
|-----|------|------|
| **数据驱动** | 真实、自然、能发现意外模式 | 可能有噪音、质量参差不齐 |
| **专家规则** | 高质量、结构化、经过验证 | 可能覆盖不全、不够灵活 |

**混合系统的设计思路：**

1. **专家经验作为"骨架"**
   - 用 Excel 里的场景分类和标签体系作为基础框架
   - 专家话术作为"黄金模板"

2. **真实数据作为"血肉"**
   - 从真实会话中挖掘更多变体
   - 用数据来发现专家没覆盖到的场景
   - 用数据来验证和优化专家规则

3. **反馈闭环**
   - 人工审核时，可以标记"这个模板像专家写的"或"这个模板需要改进"
   - 逐步让系统学会区分"专家级话术"和"普通话术"

## 七、总结

这个 Excel 文件不是"另一个数据源"，而是**媒介团队的认知框架和方法论**。

我们当前的项目是在"做记录"（把会话存下来、结构化），而这个文件告诉我们"该怎么理解"这些记录。

**我的核心建议：**
- 不要把这个文件里的话术直接"扔进"我们的数据库
- 而是把它作为**评估标准**和**补充素材**
- 用它来优化我们的标签体系、弱规则、模板质量
